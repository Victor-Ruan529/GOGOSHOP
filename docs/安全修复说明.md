# 安全修复说明

本次加固修复了原项目中的 15 个安全问题和 6 个业务/代码缺陷。每一项都可以用 `scripts/smoke-test.sh` 自动验证（共 57 项检查）。

## 一、高危

| # | 问题 | 风险 | 修复 | 涉及代码 |
|---|---|---|---|---|
| S1 | 注册接口接受 `role: "ADMIN"` | 任何人都能注册管理员，接管整个系统 | 注册只允许 `USER` / `BUSINESS`；注册时只拷贝用户名、密码、名称、电话、邮箱，忽略 `role`、`status`、`id` | `WebController.register`、`AbstractAccountService.register` |
| S2 | `/files/**` 整个免登录 | 匿名上传任意文件、删除任意文件 | 改为注解式放行：只有 `GET /files/{name}` 公开；上传需要登录；删除仅限管理员 | `FileController`、`@PublicApi` |
| S3 | 上传不校验类型、保留原始文件名 | 上传 html/svg 造成存储型 XSS；文件名可能带 `../` | 扩展名白名单，并校验文件头（magic number）；文件名由服务端生成 `时间戳-随机串.扩展名` | `FileStorageService.store` |
| S4 | 读取/删除文件时直接拼接路径 | 路径穿越，可读取或删除服务器上的其他文件 | 拒绝包含 `/`、`\`、`..` 的文件名；`normalize()` 后必须仍在上传目录内 | `FileStorageService.resolve` |
| S5 | 所有接口只检查是否登录，不检查角色 | 普通用户可以调用管理员接口，增删管理员、商家、用户 | 新增 `@RequireRole` 注解，由拦截器统一校验，按权限矩阵标注到各接口 | `JwtInterceptor`、各 Controller |
| S6 | 越权访问（IDOR） | 遍历 id 就能查看、修改、删除别人的订单、商品、收藏 | Service 层统一做归属校验：商家只能操作本店商品和订单，用户只能操作自己的订单和收藏 | `GoodsService.checkOwner`、`OrdersService.getAccessible`、`CollectService` |
| S7 | 下单时信任前端传来的 `userId`、`businessId`、`status` | 冒充他人下单；直接把订单写成“已完成” | 前端只传 `goodsId` 和 `quantity`，其余字段全部由服务端根据 token 和商品数据生成 | `OrdersService.create` |
| S8 | 密码明文存储、明文比较 | 数据库泄露即所有账号泄露 | 改为 BCrypt 哈希；兼容旧数据：明文密码登录成功后自动升级为哈希 | `AbstractAccountService.passwordMatches` |
| S9 | 登录及各查询接口返回 `password` 字段 | 密码随接口响应泄露到前端和 localStorage | `password`、`newPassword` 标记为 `@JsonProperty(WRITE_ONLY)`，永不序列化 | `Account` |
| S10 | JWT 直接用用户密码作为签名密钥 | 知道某人密码就能伪造他的 token，且没有服务端密钥 | 密钥改为 `服务端密钥 + 密码哈希`，服务端密钥从环境变量 `JWT_SECRET` 读取 | `TokenUtils` |
| S11 | `/updatePassword` 按请求体中的 `username` 修改 | 知道别人旧密码即可修改，且不受登录身份约束 | 只修改当前 token 对应账号的密码；改密后旧 token 失效 | `WebController.updatePassword` |

## 二、中危

| # | 问题 | 修复 |
|---|---|---|
| S12 | 无登录失败限制，可暴力破解 | 同一账号连续失败 5 次锁定 10 分钟（可配置）；“用户不存在”和“密码错误”返回相同提示，防止枚举用户名 |
| S13 | CORS 允许 `*` | 改为白名单，通过 `CORS_ORIGINS` 配置 |
| S14 | 拦截器支持从 URL 参数读取 token | token 会进入服务器日志、浏览器历史和 Referer，已改为只从请求头读取 |
| S15 | 数据库密码写死在配置文件，未知异常直接返回 | 数据库账号、JWT 密钥等都支持环境变量覆盖；全局异常处理只返回通用提示，详细堆栈只写日志 |

其他加固：

- 商家不能通过“修改个人资料”把自己的审核状态改成“审核通过”；
- 未审核通过的商家不能发布商品（原来只在前端判断）；
- 管理员不能删除自己；
- 分页大小上限 100，防止一次查询拉取全表；
- 上传大小限制从 100MB 降到 10MB；
- 图片以正确的 `image/*` 类型返回，并带 `X-Content-Type-Options: nosniff`。

## 三、业务与代码缺陷

| # | 问题 | 修复 |
|---|---|---|
| B1 | 订单不存成交价，查询时 join 商品表 | 下单时保存商品快照（名称、图片、单价、单位），新增数量和总价 |
| B2 | 下单不扣库存，会超卖 | 新增 `stock` 字段；在事务中用 `WHERE stock >= ?` 原子扣减，库存不足时回滚 |
| B3 | 订单号用时间戳生成，并发时会重复 | 改用雪花算法，数据库加唯一约束；以字符串返回，避免 JS 精度丢失 |
| B4 | 订单状态可以被改成任意值 | `OrderStatusEnum` 定义状态机；更新语句带旧状态条件，防止并发重复操作；取消订单时回退库存 |
| B5 | `GoodsService.selectPage` 对普通用户也设置了 `businessId = 用户id` | 删除错误逻辑 |
| B6 | 多表 join 时 `where id = ?` 字段有歧义，查询直接报错 | 所有 join 查询的字段都加上表名前缀 |

前端同步修复：

- 上传组件统一携带 token；
- 表单校验规则把提示字段误写成了 `name` / `img`（应为 `message`），导致提示不显示；
- 前台和后台路由重名（`Home`、`Type`、`Orders`）；
- 收到 401 时清除本地登录信息再跳转；
- 路由守卫按角色区分前台和后台；
- 生产环境地址 `.env.production` 配置错误（`http://:9090`）。

## 四、如何验证

```bash
# 1. 重置数据库
psql -h localhost -U postgres -d gogoshop -f db/schema.sql
psql -h localhost -U postgres -d gogoshop -f db/data.sql

# 2. 启动后端
cd springboot && ./mvnw spring-boot:run

# 3. 另开一个终端，运行冒烟测试（会写入测试数据）
bash scripts/smoke-test.sh

# 4. 单元测试
cd springboot && ./mvnw test
```

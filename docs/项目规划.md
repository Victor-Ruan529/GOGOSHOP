# GOGO购商城 项目规划

## 1. 项目定位

GOGO购是一个多商家电商平台，有三种角色：

- **用户**：浏览商品、搜索、收藏、下单、取消订单、确认收货；
- **商家**：注册后等待审核，审核通过后发布和管理商品、处理本店订单（发货）；
- **管理员**：管理账号、审核商家、维护分类、公告和轮播图，查看全部订单。

这个项目原本是本科阶段的课程项目，当前目标是把它整理成一个**能直接运行、安全可靠、可以写进简历**的作品，再逐步加入有技术亮点的功能。

## 3. 后续路线图

按“投入小、收益大”的顺序排列，每个阶段都可以单独完成。

### 阶段四：核心电商功能（建议优先）

| 功能 | 说明 | 技术点 |
|---|---|---|
| 购物车 | 加入购物车、修改数量、合并下单 | 新增 `cart` 表；一个订单包含多个商品（`orders` + `order_item` 拆表） |
| 收货地址 | 地址簿，下单时选择地址 | 地址写入订单快照 |
| 模拟支付 | 新增“待支付”状态，超时未支付自动取消 | 支付宝沙箱；用 `@Scheduled` 或延时队列关闭超时订单 |
| 商品上下架 | 下架后前台不可见、不可下单 | `goods.status` 字段 |
| 商品评价 | 确认收货后可评价 | 评价表，商品详情页展示评分 |

### 阶段五：工程化

| 事项 | 说明 |
|---|---|
| Docker Compose | 一条命令启动 PostgreSQL、后端和 Nginx（托管前端静态文件） |
| 数据库迁移工具 | 引入 Flyway，用版本化脚本代替手动执行 `schema.sql` |
| 接口文档 | 引入 springdoc-openapi，自动生成 Swagger 文档 |
| CI | GitHub Actions：每次推送自动运行 `./mvnw test` 和前端构建 |
| 集成测试 | 用 Testcontainers 启动真实的 PostgreSQL，对 Mapper 和下单流程做集成测试 |
| 统一参数校验 | DTO + `@Valid`，替换 Service 里的手写校验 |

### 阶段六：性能与亮点（面试加分项）

| 事项 | 说明 |
|---|---|
| Redis 缓存 | 缓存首页热门商品、分类；登录失败计数放到 Redis，支持多实例部署 |
| 秒杀 | Redis 预扣库存 + 消息队列异步下单，限流防刷 |
| 全文搜索 | PostgreSQL `tsvector` 或 Elasticsearch，支持中文分词 |
| 对象存储 | 图片改存 MinIO / OSS，数据库只存相对路径 |
| 技术栈升级 | Spring Boot 3 + JDK 17/21（`javax` 改为 `jakarta`），前端升级到 Vue 3 + Vite + Element Plus |

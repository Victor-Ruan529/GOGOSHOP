# GOGO购商城 系统架构

## 1. 总体架构

前后端分离的单体应用：Vue 单页应用通过 HTTP + JSON 调用 Spring Boot 后端，后端用 MyBatis 访问 PostgreSQL，上传的图片保存在本地 `files/` 目录。

```mermaid
flowchart LR
    subgraph Browser[浏览器]
        FE[Vue 2 + Element UI<br/>前台商城 / 后台管理]
    end
    subgraph Server[Spring Boot 2.7 · :9090]
        CORS[CorsFilter<br/>白名单跨域]
        JWT[JwtInterceptor<br/>认证 + 角色授权]
        C[Controller]
        S[Service<br/>业务规则 / 越权校验 / 事务]
        M[MyBatis Mapper]
        FS[FileStorageService]
    end
    DB[(PostgreSQL 16<br/>gogoshop)]
    Disk[(files/ 图片目录)]

    FE -- "token 请求头" --> CORS --> JWT --> C --> S --> M --> DB
    S --> FS --> Disk
```

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue 2.6、Vue Router 3、Element UI 2、axios | `/front/*` 为用户商城，`/` 下为管理员和商家的后台 |
| 接入层 | CorsFilter、JwtInterceptor | 跨域白名单；所有接口默认需要登录，`@PublicApi` 放行，`@RequireRole` 限制角色 |
| 控制层 | Spring MVC `@RestController` | 只做参数接收和结果包装，统一返回 `Result{code,msg,data}` |
| 业务层 | Spring `@Service` | 数据归属校验、订单状态机、库存扣减事务、密码哈希 |
| 持久层 | MyBatis 3.5 + PageHelper | SQL 写在 `resources/mapper/*.xml`，全部使用 `#{}` 预编译参数 |
| 数据库 | PostgreSQL 16 | 外键、唯一约束、CHECK 约束保证数据一致性 |
| 存储 | 本地磁盘 | 图片文件名由服务端生成，读取时做路径穿越校验 |

## 3. 认证与授权

### 3.1 登录与请求认证流程

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant W as WebController
    participant A as AccountService
    participant I as JwtInterceptor
    participant DB as PostgreSQL

    B->>W: POST /login {username, password, role}
    W->>A: login()
    A->>A: 检查是否被锁定（连续失败 5 次锁 10 分钟）
    A->>DB: 按用户名查询
    A->>A: BCrypt 校验密码
    A-->>B: 账号信息 + token（不含密码）
    Note over B: token 存入 localStorage

    B->>I: GET /orders/selectPage<br/>Header token: xxx
    I->>I: 解析 token 得到 id 与角色
    I->>DB: 查询账号，取得密码哈希
    I->>I: 用 密钥+密码哈希 验签、检查过期
    I->>I: 检查 @RequireRole
    I->>I: 当前账号放入 request
    I-->>B: 放行后由 Service 按归属过滤数据
```

**token 设计**：载荷为 `用户id-角色`，有效期 2 小时，签名密钥为 `服务端密钥 + 用户密码哈希`。

- 只有服务端密钥的持有者能签发 token；
- 用户修改密码后，之前签发的 token 立即失效；
- token 只从请求头读取，不接受 URL 参数。

### 3.2 两层权限控制

1. **接口层（角色）**：`JwtInterceptor` 读取 `@RequireRole`，角色不匹配返回 `403`。
2. **数据层（归属）**：Service 内校验“这条数据是不是你的”，例如商家只能改自己店铺的商品，用户只能看自己的订单。

## 4. 数据模型

```mermaid

    business ||--o{ orders : "接单"

    goods ||--o{ orders : "快照来源"
    goods ||--o{ collect : ""

    admin {
        int id PK
        varchar username UK
        varchar password "BCrypt"
    }
    users {
        int id PK
        varchar username UK
        varchar password "BCrypt"
        varchar phone
    }
    business {
        int id PK
        varchar username UK
        varchar password "BCrypt"
        varchar status "审核中/审核通过/审核不通过"
    }
    type {
        int id PK
        varchar name
        varchar img
    }
    goods {
        int id PK
        numeric price "CHECK >= 0"
        int stock "库存 CHECK >= 0"
        int count "销量"
        int type_id FK
        int business_id FK
    }
    orders {
        int id PK
        bigint order_id UK "雪花ID"
        int user_id FK
        int goods_id FK
        varchar goods_name "快照"
        numeric goods_price "快照"
        int quantity
        numeric total_price
        varchar status
        timestamp create_time
    }
    collect {
        int id PK
        int user_id FK
        int goods_id FK "UNIQUE(user_id, goods_id)"
    }
    notice {
        int id PK
        varchar title
        date time
    }
    carousel {
        int id PK
        varchar img
        date time
    }
```

设计要点：

- **订单快照**：下单时把商品名、图片、单价、单位写进订单，商家改价或删除商品不影响历史订单。
- **金额**：数据库用 `NUMERIC`，Java 用 `BigDecimal`，避免浮点误差。
- **订单号**：雪花算法生成 19 位 `BIGINT`。返回给前端时转成字符串，因为 JS 的 Number 只能精确表示 2^53 以内的整数。
- **`users` 表名**：`user` 是 PostgreSQL 保留字，所以普通用户表命名为 `users`。

## 5. 订单状态机

```mermaid
stateDiagram-v2
    [*] --> 待发货: 用户下单（扣库存）
    待发货 --> 已发货: 商家/管理员发货
    待发货 --> 已取消: 用户取消（回退库存）
    已发货 --> 已完成: 用户确认收货
    已完成 --> [*]: 可删除
    已取消 --> [*]: 可删除
```

- 状态流转规则集中在 `OrderStatusEnum.canTransitTo()`，有单元测试覆盖；
- 更新状态的 SQL 带旧状态条件（`WHERE id=? AND status=?`），并发重复操作只有一次会成功；
- 下单的扣库存语句是 `UPDATE goods SET stock = stock - ? WHERE id = ? AND stock >= ?`，与插入订单在同一个事务里，库存不足时整体回滚，不会超卖。

## 6. 配置项

所有敏感配置都可以用环境变量覆盖（见 `application.yml`）：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/gogoshop` | 数据库连接 |
| `DB_USERNAME` / `DB_PASSWORD` | `postgres` / `123456` | 数据库账号（仅本地开发默认值） |
| `JWT_SECRET` | 开发用默认值 | **生产环境必须修改** |
| `CORS_ORIGINS` | `http://localhost:8080,http://127.0.0.1:8080` | 允许跨域的前端地址 |
| `FILE_UPLOAD_DIR` | 自动查找项目根目录下的 `files/` | 图片目录 |
| `FILE_BASE_URL` | `http://localhost:9090` | 返回给前端的图片地址前缀 |
